# 픽스팟 시연 영상 촬영 시나리오

목표 길이 약 3분 20초 · 가로 1920×1080 권장 · 차량 앱 0.27.0과 동승자 웹의 실제 동작 화면

운전자와 동승자가 이동 부담을 비교하고 같은 지점을 확정하는 과정을 보여줍니다. 참가부터 후보 비교, 명시적 확정과 변경, Pleos 시간·거리 조회, 종료까지 한 만남의 흐름으로 구성합니다. 아래 시간은 편집 목표이며 공식 영상 길이 제한을 의미하지 않습니다.


## 촬영 전에 준비할 것

1. Pleos 가상 차량을 부팅한 뒤 프로젝트의 competition-demo.command를 실행합니다. 같은 Mac에서 http://127.0.0.1:8788/을 엽니다. 터미널은 실행 상태로 둡니다. 이 주소를 휴대폰 접속 주소로 안내하지 않습니다.

2. 차량은 정차·조작 가능 상태로 준비하고 새 만남을 시작합니다. 오래된 코드는 재사용하지 않습니다. 후보는 계산 후 30분, 만남은 시작 후 60분 유지됩니다.

3. 차량 화면과 동승자 브라우저를 각각 녹화합니다. 전체 데스크톱보다 앱 콘텐츠 영역을 중심으로 잡아 계정 프로필, 알림, 개인 폴더 경로가 보이지 않게 합니다. 영상에 개인정보가 담긴 지원서나 비밀 설정 파일을 열지 않습니다.

4. 내레이션은 별도로 녹음해 편집합니다. 현재 가상 차량의 마이크·소리는 오류 때문에 꺼져 있으므로 차량 음성 기능을 사용하는 장면을 넣지 않습니다.

5. 화면에서 버튼을 누른 뒤 결과를 2~3초 유지합니다. 후보 비교와 확정은 카드·버튼·웹 결과가 읽히도록 확대합니다. 대기 시간을 줄여 편집할 수 있지만 실패 응답을 성공 화면으로 바꾸지 않습니다.

6. 시작 자막에 “Pleos Connect 가상 차량과 동승자 웹의 프로토타입”을, 후보 비교 장면에는 “지정 위치·고정 비교값 / 실시간 교통 미반영”을 표시합니다. Pleos 조회 장면은 “실제 SDK 응답”으로 구분합니다.


## 촬영 순서와 결과

차량 새 만남 → 웹 코드 참가 → 지정 위치 공유 동의 → 세 가지 선호 비교 → B 카드 미리보기 → B 확정 → C 카드 미리보기 → C 변경 확정 → Pleos 조회 → 웹 종료 → 차량 종료 화면. 카드만 누른 상태와 확정한 상태가 다르다는 점을 반드시 보여줍니다.

제출본은 연결 시연용 debug 앱의 영상입니다. release APK는 오프라인 후보 비교 구성이라는 차이를 README와 지원서에 남깁니다. debug 파일 이름만 release로 바꾸지 않습니다.


## 장면별 촬영과 내레이션


### 01 문제와 앱 소개 00:00–00:15

조작과 화면: 차량의 후보 비교 화면을 짧게 보여준 뒤 새 만남 화면으로 전환합니다.

내레이션: “같은 장소에서 만나기로 했는데, 차는 돌아가야 하고 사람은 멀리 걸어야 할 때가 있습니다. 픽스팟은 운전자와 동승자의 이동 부담을 함께 비교해 만날 곳을 정합니다.”

확인할 것: 앱명과 한 줄 소개. 차량 앱이 중심이라는 점을 먼저 보여줍니다.


### 02 만남 연결 00:15–00:35

조작과 화면: 차량의 새 만남과 참여 코드 → 동승자 웹 코드 입력 → 만남에 참여하기를 순서대로 보여줍니다.

내레이션: “운전자가 만남을 만들면 동승자는 앱 설치 없이 웹으로 참여합니다. 이번 연결은 같은 컴퓨터의 웹과 Pleos 가상 차량을 사용합니다.”

확인할 것: 코드는 촬영 직전에 새로 생성합니다. 실제 휴대폰 초대 링크와 섞어서 같은 연결인 것처럼 편집하지 않습니다.


### 03 위치 공유 동의 00:35–00:50

조작과 화면: 웹의 지정 위치 안내 → 공유 동의 체크 → 이 위치 공유하기 → 차량 후보 등장.

내레이션: “동승자는 공유할 위치를 확인하고 동의한 뒤 공유합니다. 여기서는 실제 기기 위치 대신 양재·매봉의 지정 위치를 사용합니다.”

확인할 것: 동의 이전 화면과 동의 후 화면을 모두 담습니다. 위치 권한 팝업을 가짜로 추가하지 않습니다.


### 04 후보와 선호 비교 00:50–01:20

조작과 화면: 균형 기본 상태를 3초 → 도보 짧게 → 우회 적게 → 균형 있게로 복귀합니다.

내레이션: “A는 도보 230미터와 차량 우회 2분, B는 도보 90미터와 우회 5분, C는 도보 480미터와 우회 45초입니다. 많이 걷기 어려우면 도보를, 차량의 동선이 중요하면 우회를 우선해 비교할 수 있습니다.”

확인할 것: 후보의 이름과 수치를 읽을 수 있게 잡습니다. 배치도는 위치 관계도이며 실제 도로 지도라고 설명하지 않습니다.


### 05 미리보기와 확정 01:20–01:45

조작과 화면: B 카드를 선택합니다. 확정 버튼을 누르기 전에 웹 선택 대기를 보여줍니다. 그다음 이 지점에서 만나기를 누르고 차량·웹 B 확정을 함께 보여줍니다.

내레이션: “카드를 누르는 것은 미리보기입니다. 이 지점에서 만나기를 눌러야 약속 장소가 전달됩니다. 이제 차량과 동승자는 같은 B 지점을 확인합니다.”

확인할 것: 웹의 B, 도보 2분, 우회 5분과 차량 확정 완료 표시를 함께 확인합니다.


### 06 확정 지점 변경 01:45–02:05

조작과 화면: C 카드를 누릅니다. 웹은 B를 유지하는 장면을 2초 담습니다. 이 지점으로 변경 → 웹 C 반영.

내레이션: “다른 후보를 살펴봐도 기존 약속은 유지됩니다. 변경을 확정하면 양쪽 화면이 C로 바뀌어, 검토 중인 장소와 실제 만날 장소가 섞이지 않습니다.”

확인할 것: 변경 전 B 유지와 변경 후 C, 도보 7분·우회 45초를 대비합니다.


### 07 Pleos 차량 이동 정보 02:05–02:35

조작과 화면: 시간·거리 확인을 누르고 요청 중 표시 → 성공한 실제 응답 화면을 녹화합니다. 필요하면 오른쪽 패널만 확대합니다.

내레이션: “차량에서 선택 지점까지의 시간과 거리는 Pleos NaviHelper로 조회합니다. 이 결과는 앞의 후보 비교값과 구분됩니다. 조회만 수행하며 기존 내비 안내는 유지합니다.”

확인할 것: 실제 반환값을 그대로 사용합니다. 미리 정한 숫자를 내레이션에 넣지 않습니다. 자동 경유지 등록이나 안내 시작이라고 말하지 않습니다.


### 08 만남 종료 02:35–02:55

조작과 화면: 웹 공유 종료하기 → 웹 종료 안내 → 차량 종료 안내와 새 만남 시작 버튼을 보여줍니다.

내레이션: “만남을 마치면 공유를 종료합니다. 차량과 웹 모두 종료 상태로 바뀌고 다음 만남을 시작할 수 있습니다.”

확인할 것: 두 화면의 종료 결과를 확인한 다음 장면을 마칩니다.


### 09 구현 범위와 마무리 02:55–03:20

조작과 화면: 후보 비교·확정·Pleos 조회 장면을 짧게 재배치하고 구현 범위 자막으로 마칩니다.

내레이션: “픽스팟은 후보 비교부터 지점 확정과 변경, 공유 종료까지 연결했습니다. 현재 비교 수치는 고정 데이터이고 Pleos 이동 정보는 실제 SDK 응답입니다. 실제 위치와 경로의 통합, 지도와 음성은 다음 개발 단계입니다.”

확인할 것: 마지막 자막: “구현: 비교·확정·변경·공유 종료·Pleos 조회 / 후속: 실제 데이터 통합·지도·음성”. 자동 경유지 추가는 현재 비활성이라고 설명란에 기재합니다.


## 촬영 중 문제가 생겼을 때

참가 코드가 만료되면 차량에서 새 만남을 만들고 웹도 다른 만남에 참여하기로 돌아갑니다. 이후 연결 장면부터 다시 찍습니다.

후보가 사라지면 중앙의 경로 다시 계산을 사용합니다. 후보가 보이는 상태의 재계산은 하단 만남 설정 안에 있습니다. 횟수가 소진됐으면 새 만남으로 다시 시작합니다.

Pleos 조회가 실패하면 오류 표시를 그대로 남기고 연결 상태를 확인한 뒤 다시 촬영합니다. 성공을 확인하지 못하면 해당 장면을 성공 시연으로 사용하지 않습니다. 실제 과거 검증 결과를 설명 자료에 적는 것과 이번 화면이 성공한 것처럼 편집하는 것은 구분합니다.

가상 차량 자동 클릭 도구가 실패하더라도 녹화는 수동 버튼 조작으로 진행할 수 있습니다. 이번 영상은 운전자가 직접 화면을 조작하는 과정을 담습니다.

화면이 잘리면 시스템 해상도를 바꾸기 전에 Android Studio의 가상 차량 표시 배율을 조정하고 촬영 영역을 확인합니다. 앱의 상단·세 후보·확정 버튼·하단 종료 버튼이 모두 들어가야 합니다.


## 녹화 후 확인

영상에 실명·이메일·휴대폰·서명·개인 알림·API 키가 없는지 확인합니다.

“고정 비교값”과 “실제 Pleos 조회” 자막을 남깁니다. 정차 가능 장소를 보증하거나 내비 안내를 시작했다고 표현하지 않습니다.

B 확정, C 변경, 양쪽 종료 장면이 순서대로 들어갔는지 확인합니다. 버튼 클릭 직후 화면이 바뀌기 전에 잘라내지 않습니다.

영상 파일명 예: Pickspot_demo_20261115.mp4. 업로드 후 비로그인 상태에서 심사자가 볼 수 있는지 확인합니다. 공개 계정명에 참가자 신원이 드러나는지도 확인합니다.

개인정보가 들어간 참가신청서는 GitHub에 올리지 않습니다. 저장소 주소·최종 커밋·APK 경로·영상 링크는 제출 이메일에 별도로 정리합니다.


## 시간이 부족할 때의 90초 구성

문제 소개 10초 → 참가·공유 15초 → 후보 비교 15초 → B 확정 15초 → C 변경 10초 → Pleos 조회 15초 → 종료 10초. 순서를 유지하되 반복 클릭과 대기 구간을 줄입니다. 실제 응답과 확정 전후의 차이를 생략하지 않습니다.
